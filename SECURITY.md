# Security Policy

## Supported versions

This repository is an educational project rather than a deployed service. Security fixes are applied to the latest version on the default branch; older snapshots are not maintained.

## Reporting a vulnerability

Do not open a public issue for a vulnerability, exposed credential, or other sensitive report.

Use [GitHub's private vulnerability-reporting flow](https://github.com/MarioOrellana58/data-engineering-interviews-study-guide/security/advisories/new).

If private reporting is not yet available, contact the repository owner through their GitHub profile before sharing details. Include the affected files, impact, reproduction steps, and any suggested mitigation. Remove real credentials and personal data from examples. Maintainers will aim to acknowledge the report within seven days and will coordinate disclosure after a fix is available.

For incorrect educational content that has no security impact, use the content-correction issue template instead.
